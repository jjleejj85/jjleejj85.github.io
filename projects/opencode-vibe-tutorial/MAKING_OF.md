## v0.4 - 2025-09-17

### 原始 Prompt
接下来做 v0.4，把「安装 OpenCode」这一节做出来，其他章节先不要动。

我希望这里尽量简单，不要把官方文档里的所有安装方法都堆给学生。

可以分成 Desktop 和 CLI 两种方式：

Desktop：
- macOS、Windows、Linux 都可以从 OpenCode 官方 Download 页面下载
- macOS 也可以用 Homebrew：
  brew install --cask opencode-desktop

CLI：
- macOS / Linux 可以用官方安装脚本：
  curl -fsSL https://opencode.ai/install | bash
- Windows 官方目前更推荐通过 WSL 使用 OpenCode，再在 WSL 中安装
- 其他 npm、Bun、Chocolatey、Scoop 等方式不用全部展开，可以提示学生去官方文档查看

我希望 Desktop / CLI 和不同系统之间可以比较直观地切换，安装命令要有复制按钮。

另外放一个明显但不抢眼的「查看官方安装页面」入口：
https://opencode.ai/zh/download

整体继续沿用现在的视觉风格，重点是让第一次接触 OpenCode 的学生知道"我该去哪里下载、最简单怎么装"，不要做成复杂的安装手册。

## 开发记录规则（v0.1 后更新）

1. 每个重要版本继续使用 Git commit 保存。
2. 每个正式版本继续使用 v0.1、v0.2、v0.3……这样的 Git tag。
3. MAKING_OF.md 每一轮记录：原始 Prompt（必须是用户原文，不得改写）、目标、主要变化、涉及文件、Tag 版本号。不需要记录 commit hash。
4. 每一轮只做一个 commit：先完成网页修改和 MAKING_OF.md，再统一 commit，然后给该 commit 打 tag。不要为了补充文档内容再做额外 commit。
5. 现在不要复制项目文件，也不要创建 versions/ 目录，避免项目里出现大量重复版本。
6. 等网站主体完成后，再根据 Git tags，把需要展示的历史版本统一导出到 versions/v0.1、versions/v0.2……目录。
7. 最终 Making of 会通过 iframe 或类似的小型浏览窗口，直接加载这些历史版本，让学生真正浏览每一个阶段的网站。
8. 如果某个历史版本以后无法正常嵌入，再单独考虑截图作为 fallback。
